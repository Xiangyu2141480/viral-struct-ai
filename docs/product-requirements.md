# Product Requirements / 拿奖导向需求说明

## 1. 项目目的

本项目要做的不是一个通用剪辑器，也不是一个只会写脚本的 AI 工具，而是一个面向短视频创作的 **爆款结构迁移引擎**：

```txt
样例视频理解 -> 结构抽取 -> 新内容与素材适配 -> 素材缺口识别 -> 缺口补全 -> 可解释结果生成
```

评委需要看见的核心能力是：

- 我们如何定义视频的“结构”。
- 我们如何从样例中抽取结构，而不是复制内容。
- 我们如何把结构迁移到新的主题、商品信息或用户素材。
- 当素材不足时，系统如何识别缺口并做合理补全。
- 最终结果为什么这样生成，是否可解释、可调整、可展示。

## 2. 成功标准

目标不是“跑通一个 demo”而已，而是围绕评分表最大化拿分：

| 目标 | 成功标准 |
|---|---|
| P0 基础闭环 | 上传样例、展示基础解析、抽取结构、输入新内容、生成脚本/分镜/时间线/包装建议 |
| 素材缺口处理 | 槽位级识别 missing/partial/matched，并给出补全策略 |
| 可视化展示 | 清楚展示样例结构、迁移映射、素材缺口、补全策略、最终结果 |
| 进阶能力 | 包装生成、多版本、人机调整优先做高性价比版本 |
| 答辩可信度 | 文档能说明 AI 架构、工具协议、安全边界、AI 工具使用和自主设计 |

## 3. 用户流程

```txt
1. 用户上传 1 条或多条样例视频。
2. 系统解析视频基础信息：时长、分辨率、封面、关键帧、镜头数、字幕/语音概览。
3. 系统抽取脚本结构、节奏结构、包装结构，生成 ViralStructureGraph。
4. 用户输入新主题/商品卖点，并上传有限素材。
5. 系统生成 AssetCard，并把素材匹配到结构槽位。
6. 系统识别缺口：开头吸引镜头、商品特写、使用过程、对比、CTA 等。
7. 系统生成补全策略：文案/字幕补全、包装补全、素材复用、AIGC 建议。
8. 系统输出脚本、分镜、时间线草案、包装建议和可展示 demo。
9. 用户调整 hook、卖点顺序、包装风格或节奏，系统重新生成。
```

## 4. P0 范围

P0 必须优先完成，因为它决定 65 分以上的基础分和核心观感。

| 任务 | 必须体现 |
|---|---|
| 样例视频输入与解析 | 多样例可选；至少展示时长、镜头数、字幕/语音概览、封面/关键帧 |
| 结构拆解 | 至少做脚本结构 + 节奏结构 + 包装结构中的 2 类；冲奖版本做 3 类 |
| 新内容与素材输入 | 支持商品/主题/卖点输入；素材至少支持图片、视频、文案中的一种 |
| 结构迁移与结果生成 | 至少输出脚本 + 分镜；冲奖版本输出脚本 + 分镜 + 时间线 + 包装建议 |
| 素材缺口识别 | 每个结构槽位输出 matched / partial / missing、原因和影响 |
| 素材缺口补全 | 至少支持一种；优先做文案/字幕补全 + 包装补全 |
| 过程可视化 | 必须展示“抽取了什么、映射到哪里、缺什么、怎么补、生成什么” |
| 结果可验证 | 至少分镜/时间线可视化；冲奖版本提供 HyperFrames-first preview 或可播放 demo |

## 5. P1 与加分范围

1-2 周版本只做高性价比 P1，不追求“大而全”。

| 能力 | 推荐实现 |
|---|---|
| 画面包装生成 | 字幕样式、标题条/卖点卡、封面文案，至少 2 项 |
| 多版本生成 | 高点击版、高转化版、高节奏版，差异必须可解释 |
| 真实素材适配 | AssetCard、素材分类、适合槽位推荐、基础高光片段判断 |
| 人工可调 | hook、卖点顺序、包装风格、视频节奏、结尾表达至少 1 项可改 |
| 自然语言改片 | 作为亮点，输出 timeline patch，而不是重新黑盒生成 |

## 6. 非目标

- 不做通用剪辑器。
- 不做完整剪映替代品。
- 不训练自有大模型。
- 不依赖真实 API 才能演示，所有 AI 能力必须有 mock fallback。
- 不复制样例视频的人物、品牌、音乐、文案或受版权保护画面。

## 7. 模型与密钥策略

- 火山方舟 Doubao 优先，按 OpenAI-compatible LLM provider 抽象接入。
- 本地和答辩必须支持 mock mode，保证无网络或无 key 时 demo 可跑。
- 真实 API key 只允许写入本地 `.env`，不得进入仓库、截图、日志、文档或提交历史。
